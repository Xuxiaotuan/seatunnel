# Flink Multi-Source SQL Join POC

The `codex/flink-multi-source-join-workbench` branch provides a minimal SQL join validation for Flink 1.20.5: BATCH mode, two sources, and a single-field equi `INNER JOIN`. The SQL query determines how many input tables are used and produces one output table.

The execution order is:

```text
Source → pre_transform SQL → Python Transform → post_transform SQL → Sink
```

Both SQL stages reuse the same `StreamExecutionEnvironment`, submit one Flink job, and keep existing single-input `SeaTunnelTransform` plugins unchanged. Each nested SQL stage must declare its visible tables with `plugin_input`; `pre_transform` handles multi-source joins, while `post_transform` can read fields generated by Python and apply another filter or projection. The legacy top-level `sql { query, plugin_output }` form remains a pre-stage compatibility path and can see all upstream inputs. The example configuration is `python_transform_two_source_inner_join.conf` in `seatunnel-flink-20-example`.

This POC accepts only finite FakeSource inputs in BATCH mode; configuring a SQL stage in STREAMING mode fails fast. This avoids presenting an unbounded join without a watermark, state TTL, and recovery contract as production-ready behavior. The local run produced four source rows, two rows after `pre_transform`, and one row after the `post_transform` filter. PostgreSQL CDC, late events, time windows, state TTL, and recovery semantics for multi-level joins remain outside this POC.
